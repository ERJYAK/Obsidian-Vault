
TimerScan по оконачанию таймера начинает чтение данных из OPC-сервера методом ReadDataFromSourceServer. Этот метод вызывает ReadDataFromServer из ConnectionManagerToOpcuaServer.

Судя по логам, соединение падает в момент чтения данных по тэгам в этом методе.
По каждому тэги начинают читаться асинхронно значения. Новое лог сообщение:
```
WARN [Ошибка обновления данных в теге K:C53.U1.AGR2::PAR:AI:2Q_104K.1:FQ::FAKT: значение  не может быть приведено к типу DOUBLE]
``` 
говорит о том, что в момент чтения данных, некоторые значения невозможно сконвертировать в DOUBLE. 
Асинхронно вызываются метод ReadCurrentValuesFromOpcServerAsync, который в свою очередь читает данные с сервера. В определенный момнет чтение завершает CancellationTokenSource, что приводит к ошибке и вызове метода OnDisconnect, который пишет в лог:
```
DEBUG [Разрыв связи с OPC UA сервером]
```

Соединение успешно разрывается и очищается. Затем в лог пишется информация о прочиьтанных данных из источника. Долгое время чтения говорит о проблемах с ичтоником:
```
INFO [ReadValues from OPC UA Server for ScanClass '1' take 22956 ms]
```

Соответственно, главный поток клиента OPCUAMainTaskAsync проверяет постоянно соедниение. При очередной проверке обнаружится отсутствие соединения и вызовется метод SetUpConnectionToOpcuaServerAsync, который выдаст лог сообщение:
```
DEBUG [Attempt to connect OPC UA opc.tcp://192.168.53.2:4840]
```

и вызовет ConnectToOpcuaServerAsync. Этот метод выдаст лог:
```
[OPC UA-сервер: opc.tcp://192.168.53.2:4840]
```
затем, в этом методе вызовется получение сессии sm.GetSession() и появится сообщение:
```
INFO [При создании подключения OPCUA SecurityPolicy:
```
а вызовется функция OnConnect, затем установится содение и выведется сообщение:
```
INFO [Supported server aggreagations:opc.tcp://192.168.53.2:4840]
```

В главном потоке соединение пройдет проверку:
```
INFO [Соединение с сервером установлено.]
```

Ровно через минуту соединение снова будет потеряно.
